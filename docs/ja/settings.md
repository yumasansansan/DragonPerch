# 設定

ファイルは1つ、それを読み書きするプログラムが3つ、そして中の1行が壊れていたときの決まりが1つ。

英語版は [docs/settings.md](../settings.md) です。

## 場所

| | |
|---|---|
| Windows | `%APPDATA%\DragonPerch\dragonperchrc` |
| Linux | `$XDG_CONFIG_HOME/dragonperch/dragonperchrc`、無ければ `~/.config` の下 |

この名前は KConfig の慣習です。形式は INI で、設定プログラムからだけでなく**手で編集されることを
前提にしています**。

## 中身

```ini
[DragonPerch]
pets-per-mascot = 1
mascots =
walk-speed = 42.00
idle-interval = 9.00
outputs =
pause-for-fullscreen = true
```

| キー | 範囲 | 意味 |
|---|---|---|
| `pets-per-mascot` | 0 – 64 | **各**マスコットを何体出すか。3体を各2体で6体。 |
| `mascots` | パック id をカンマ区切り | どれを歩かせるか。**空はすべて**。 |
| `walk-speed` | 1 – 1000 | 1秒あたりのピクセル数。歩行アニメーションは42を想定。 |
| `idle-interval` | 0 – 3600 | 自発的に立ち止まるまでの平均秒数。0で立ち止まらない。 |
| `outputs` | モニタ名をカンマ区切り | どこを歩いてよいか。**空はすべて**。 |
| `pause-for-fullscreen` | `true` / `false` | 全画面表示中のモニタでは隠す。 |

空が「すべて」を意味するのは意図的で、チェックを全部外すと「何も無し」ではなく空リストが保存されるのも
そのためです。来年インストールされたマスコットは、それ以前に書かれたリストから漏れるのではなく、
含まれるべきだからです。

モニタ名はシステムが報告する名前そのものです — Windows なら `\\.\DISPLAY1`、Wayland なら `DP-1` の
ようなコネクタ名。人が付けた表示名ではありません。ここを別の場所から取ってきたために、
**Windows の設定ウィンドウがデーモンの決して一致させられない識別子を保存し、全画面から竜が消えた**
ことがあります。

## 読めない行があったとき

**1行の誤りは、その行だけを失います。** 範囲外の値は丸められ、数値でない値は既定値のまま、
`key = value` の形ですらない行は読み飛ばされます。同じことが2回書かれている場合 — キーの重複や、
セクションを開き直した場合 — は**後に書かれたほうが勝ちます**。INI の慣習であり、KConfig の読み方でもあります。

以前はそうではありませんでした。デーモンは1行読めないだけで**すべての設定を既定値に戻して**おり、
そのためデーモンと設定プログラムが「ユーザが何を選んだか」について食い違い、どちらも何も言いませんでした。
現在は、意地の悪いファイルの集合を両方に通して突き合わせています。

スプライトパックの定義は同じパーサを逆の設定で読みます。半分しか読めないパックは間違ったスプライトを
指しているので、推測せずに拒否します。

## 設定プログラム

### Windows

トレイメニューの**設定**。`DragonPerch.Shell.exe` の一部で、Fluent のトレイメニューを描くのと同じ
任意インストールの WinUI 3 プログラムです。何者でなぜ別プロセスなのかは[実行のしかた](running.md)に。

### Linux

KDE 設定モジュール `kcm_dragonperch` です。トレイメニューの**設定**が

```bash
kcmshell6 kcm_dragonperch
```

を起動し、同じモジュールがシステム設定にも現れます。KDE を使っている人が最初に探す場所だからです。
`kcmshell6` が無い環境では、メニュー項目は淡色表示のままです。

Qt と KDE Frameworks を要求するのはこのプロジェクトでここだけで、デーモンはどちらも無い環境で
ビルドできなければならないので、明示したときだけビルドされます:

```bash
cmake --preset linux-x64 -D DRAGONPERCH_BUILD_KCM=ON
```

Debian では `dragonperch-kde` という別パッケージになっています。[パッケージ](packages.md)を参照。

### どちらも、そしてデーモン

保存はファイル全体を書き、そのあとデーモンに読み直しを頼みます（Windows は `WM_COPYDATA`、Linux は
セッションバスの `org.dragonperch.Control1.Reload`）。ウィンドウを閉じ終える前に画面へ反映されます。
適用を押すまで何も反映されません。キーを叩くたびに反映する設定ウィンドウは、数字を入力している途中で
竜が湧き直す設定ウィンドウです。

速さの変更は立っている竜にそのまま効きます。マスコットの変更は湧き直しになります。それ以外に方法が
ないためです。

コマンドラインの `--pets N` は、ファイルを書き換えずにその実行のあいだだけ `pets-per-mascot` を
上書きします。
