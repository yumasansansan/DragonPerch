# 設定

設定ファイルは1つ、それを読み書きするプログラムは3つ。そして、どこかの行が壊れていたときにどうなるかの話です。

英語版は [docs/settings.md](../settings.md) です。

## 場所

| | |
|---|---|
| Windows | `%APPDATA%\DragonPerch\dragonperchrc` |
| Linux | `$XDG_CONFIG_HOME/dragonperch/dragonperchrc`（設定されていなければ `~/.config/dragonperch/dragonperchrc`） |

名前は KConfig の慣習に倣ったものです。中身は INI で、設定プログラムが書き換えるだけでなく、**エディタで直接書き換えることも想定**しています。

## 中身

```ini
[DragonPerch]
pets-per-mascot = 1
mascots =
walk-speed = 42.00
idle-interval = 9.00
outputs =
pause-for-fullscreen = true
```

| キー | 範囲 | 意味 |
|---|---|---|
| `pets-per-mascot` | 0 – 64 | **各**マスコットを何体ずつ表示するか。マスコットが3種類でここが2なら、合計6体になります。 |
| `mascots` | パックのIDをカンマ区切り | どのマスコットを表示するか。**空にすると「すべて」を意味します。** |
| `walk-speed` | 1 – 1000 | 1秒間に進むピクセル数。歩行アニメーションは42を想定しています。 |
| `idle-interval` | 0 – 3600 | ランダムに立ち止まるまでの平均間隔（秒）。0に設定すると立ち止まらなくなります。 |
| `outputs` | モニタ名をカンマ区切り | マスコットの表示を許可するモニタ。**空にすると「すべて」を意味します。** |
| `pause-for-fullscreen` | `true` / `false` | アプリが全画面表示されているモニタでは、マスコットを隠します。 |

空が「すべて」を意味するのは意図的です。設定画面のチェックを全部外すと、「何も出さない」ではなく空のリストが保存されます。そうしておけば、来年になって新しいマスコットを入れたときに、それが存在する前に書かれたリストから漏れることなく、ちゃんと出てきます。

モニタ名は、システムが報告してくる名前そのものです（Windows なら `\\.\DISPLAY1`、Wayland なら `DP-1` のようなコネクタ名）。人が読むための表示名ではありません。かつてこれを間違った場所から取ってしまい、**Windows の設定ウィンドウが、デーモン側では決して一致しない識別子を保存して、どの画面からもマスコットが消える**というバグを出したことがあります（[計画](../plan.md)にあります）。

## 読めない行があったとき

**1行が読めなければ、失われるのはその行だけです。**
範囲を外れた値は上限か下限に丸められ、数値でない値はその設定を既定値のままにし、`key = value` の形になっていない行は読み飛ばされます。
また、キーが重複していたり、同じセクションが再度開かれていたりして同じ設定が2回書かれている場合は、**後から書かれたものが優先されます**。これは INI の慣習であり、KConfig の解釈方法でもあります。

以前は違いました。デーモンは1行でも読めなければ**設定を丸ごと既定値に戻す**という乱暴なことをしており、その結果、ユーザーが何を選んだのかについてデーモンと設定プログラムの見解が食い違ったまま、どちらも何も言わない、という状態になっていました。
今は、意地の悪い壊れ方をした設定ファイルを両方に読ませて、答えが一致するかをテストで突き合わせています。

なお、スプライトパックの定義ファイルも同じパーサで読みますが、そちらは逆の設定です。半分しか読めないパックは間違ったスプライトを指し示すので、都合よく推測して描くくらいなら、パックごと拒否したほうがましだからです。

## 設定プログラム

### Windows

トレイメニューの**設定...** から開きます。これは `DragonPerch.Shell.exe` の一部で、Fluent のトレイメニューを描いているのと同じ、任意インストールの WinUI 3 プログラムです。
それが何者で、なぜデーモンとは別プロセスなのかは [実行のしかた](running.md) にあります。

開けるのはどちらのメニューからでも同じです。Fluent 側は自分でウィンドウを出します。デーモン自身の Win32 メニュー（シェルが入っていないか、そのクリックに間に合わなかったときに出るほう）は、動いているシェルに頼み、いなければ起動します。シェルがどこにも無いときは項目が淡色表示になります。理由は下の Linux 側と同じで、そこにあるのに何も起きない項目より、使えないと見てわかる項目のほうがましだからです。

### Linux

KDE の設定モジュール `kcm_dragonperch` です。トレイメニューの**設定**を押すと、

```bash
kcmshell6 kcm_dragonperch
```

が実行されます。同じモジュールはシステム設定の中にも現れます。KDE を使っている人が探すのは、まずそこだからです。
`kcmshell6` が入っていない環境では、トレイメニューの設定項目は淡色表示になります。

このプロジェクトで Qt と KDE Frameworks を要求するのはこのモジュールだけです。デーモン本体はどちらも入っていない環境でビルドできなければならないので、このモジュールは明示的に指定したときだけビルドされます。

```bash
cmake --preset linux-x64 -D DRAGONPERCH_BUILD_KCM=ON
```

Debian では `dragonperch-kde` という別パッケージになっています。詳細は [パッケージ](packages.md) を参照してください。

### どちらも、そしてデーモン

設定を保存すると、ファイル全体が書き直され、続けてデーモンに読み直しが要求されます（Windows なら `WM_COPYDATA`、Linux ならセッションバスの `org.dragonperch.Control1.Reload`）。おかげで、設定ウィンドウが閉じきる前に変更が画面に出ます。

「適用」を押すまで、変更は一切反映されません。キーを叩くたびに反映される設定ウィンドウでは、数値を打ち込んでいる途中でマスコットが何度もリスポーンしてしまうからです。

速さの変更は、いま歩いているマスコットにそのまま効きます。出すマスコットの種類を変えたときだけは、いったん全員消えてから出直します。他に方法がないからです。

なお、コマンドラインの `--pets N` は、設定ファイルを書き換えずに、その起動のあいだだけ `pets-per-mascot` を上書きします。
