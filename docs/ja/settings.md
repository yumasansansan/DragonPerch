# 設定

1つの設定ファイル、それを読み書きする3つのプログラム、そして「ファイルのどこかの行が壊れていた場合のルール」についての説明です。

英語版は [docs/settings.md](../settings.md) です。

## 場所

| | |
|---|---|
| Windows | `%APPDATA%\DragonPerch\dragonperchrc` |
| Linux | `$XDG_CONFIG_HOME/dragonperch/dragonperchrc`（設定されていなければ `~/.config/dragonperch/dragonperchrc`） |

この名前は KConfig の慣習に倣っています。フォーマットは INI 形式で、設定プログラムから編集されるだけでなく、**ユーザー自身がテキストエディタで直接編集することも想定**しています。

## 中身

```ini
[DragonPerch]
pets-per-mascot = 1
mascots =
walk-speed = 42.00
idle-interval = 9.00
outputs =
pause-for-fullscreen = true
```

| キー | 範囲 | 意味 |
|---|---|---|
| `pets-per-mascot` | 0 – 64 | **各**マスコットを何体ずつ表示するか。マスコットが3種類でここが2なら、合計6体になります。 |
| `mascots` | パックのIDをカンマ区切り | どのマスコットを表示するか。**空にすると「すべて」を意味します。** |
| `walk-speed` | 1 – 1000 | 1秒間に進むピクセル数。歩行アニメーションは42を想定しています。 |
| `idle-interval` | 0 – 3600 | ランダムに立ち止まるまでの平均間隔（秒）。0に設定すると立ち止まらなくなります。 |
| `outputs` | モニタ名をカンマ区切り | マスコットの表示を許可するモニタ。**空にすると「すべて」を意味します。** |
| `pause-for-fullscreen` | `true` / `false` | アプリが全画面表示されているモニタでは、マスコットを隠します。 |

空（未設定）が「すべて」を意味するのは意図的な設計です。設定画面のチェックボックスをすべて外すと、「何も表示しない」のではなく空のリストが保存されます。こうすることで、来年になって新しいマスコットがインストールされたときに、昔保存された設定ファイルのリストから除外されることなく、ちゃんと表示されるようになるからです。

モニタ名には、システムが内部で報告している名前がそのまま使われます（Windows なら `\\.\DISPLAY1`、Wayland なら `DP-1` のようなコネクタ名など）。人がつけた表示名ではありません。過去に、この名前を不適切なところから取得してしまったために、**Windows版の設定ウィンドウがデーモン側では絶対に一致しない識別子を保存してしまい、すべての画面からマスコットが消滅した**というバグ（[計画](../plan.md)参照）がありました。

## 読めない行があったとき

**1行の記述に誤りがあった場合、その行だけが破棄されます。**
範囲外の値は上限・下限に丸められ、数値でない値は既定値のままになり、そもそも `key = value` の形になっていない行は単に読み飛ばされます。
また、キーが重複していたり、同じセクションが再度開かれていたりして同じ設定が2回書かれている場合は、**後から書かれたものが優先されます**。これは INI の慣習であり、KConfig の解釈方法でもあります。

以前はそうではありませんでした。デーモンは「たった1行でも読めない行があれば**すべての設定を既定値にリセットする**」という強引な処理をしており、その結果、デーモンと設定プログラムとの間で「ユーザーが何を選んだか」についての認識が食い違っているのに、どちらもエラーを出さないという状態に陥っていました。
現在は、意地悪に作られた不正な設定ファイル群を両方に読ませて、結果が一致するかどうかをテストで突き合わせています。

ちなみに、スプライトパックの定義ファイルも同じパーサを使って読み込まれますが、そちらは逆の設定になっています。半分しか読めないパックは誤ったスプライトを参照して表示が壊れる原因になるため、都合よく推測などはせず、エラーとして拒否するようになっています。

## 設定プログラム

### Windows

トレイメニューの**設定...** から開きます。これは `DragonPerch.Shell.exe` というプログラムの一部であり、Fluent デザインのトレイメニューを描画しているのと同じ、オプション扱いの WinUI 3 プログラムです。
これが一体何者で、なぜデーモンとは別プロセスになっているのかについては、[実行のしかた](running.md) に記載されています。

### Linux

KDE の設定モジュール `kcm_dragonperch` です。トレイメニューの**設定**を押すと、

```bash
kcmshell6 kcm_dragonperch
```

が実行されます。同じモジュールが「システム設定」内にも表示されます。KDE を使っている人であれば、まず間違いなくそこを探すからです。
システムに `kcmshell6` がない環境では、トレイメニューの設定項目はグレーアウト（淡色表示）されます。

このプロジェクト内で Qt と KDE Frameworks を要求するのはこの設定モジュールだけであり、デーモン本体はどちらもインストールされていない環境でもビルドできなければならないため、このモジュールは以下のように明示的に指定したときだけビルドされます。

```bash
cmake --preset linux-x64 -D DRAGONPERCH_BUILD_KCM=ON
```

Debian では `dragonperch-kde` という別パッケージになっています。詳細は [パッケージ](packages.md) を参照してください。

### どちらも、そしてデーモン

設定を保存すると、ファイル全体が書き換えられ、その直後にデーモンに対して設定の再読み込みが要求されます（Windows では `WM_COPYDATA`、Linux ではセッションバスの `org.dragonperch.Control1.Reload` 経由）。これにより、設定ウィンドウが完全に閉じる前に変更が画面に反映されます。

「適用」ボタンが押されるまで、変更は一切反映されません。もしキーを叩くたびに即座に反映されるような設定ウィンドウだった場合、数値を入力している途中の段階でマスコットが何度もリスポーンしてしまうからです。

速さの変更は、いま立っているマスコットたちに即座に反映されます。表示するマスコットの種類を変更した場合は、一度すべて消えてからリスポーンします（それ以外の方法がないためです）。

なお、コマンドラインで `--pets N` を指定して起動した場合、設定ファイル自体は書き換えずに、その起動中だけ `pets-per-mascot` の値を上書きします。
