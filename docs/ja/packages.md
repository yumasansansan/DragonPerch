# パッケージとダウンロード

英語版は [docs/packages.md](../packages.md) です。

`main` へのビルドごとに、更新され続ける **`nightly`** プレリリースが出ます。CI の実行ごとに同じ
ファイルが14日間アーティファクトとしても付きます。どちらも1つの `install()` 規則から出るので、
テストされたものが配られます。

| ファイル | 使い方 |
|---|---|
| `dragonperch_0.1.0~…_amd64.deb` | `sudo apt install ./dragonperch_*.deb` |
| `dragonperch-kde_0.1.0~…_amd64.deb` | Plasma 用: KWin スクリプトと設定モジュール |
| `dragonperch_0.1.0~…_x86_64.tar.gz` | 好きな場所に展開して `usr/bin/dragonperch-wl` |
| `dragonperch_0.1.0~…_x64.zip` | 展開して `dragonperch.exe` |

## Debian では2つ、それ以外は1つ

`dragonperch` はデーモン・アートワーク・翻訳・デスクトップエントリで、KWin が何であるかを知りません。
`dragonperch-kde` は KWin スクリプトと設定モジュールで、これは Plasma のものです。後者は対応する
`dragonperch` にちょうど依存し、デーモン側は前者を suggests します。Plasma のデスクトップに入れたとき、
動かすために必要なもう半分が提示されるようにです。

分けたのは今のためというより**次のため**です。KWin 以外はウィンドウの位置を知る手段を自前で持つ必要が
あり（GNOME なら Shell 拡張、wlroots なら `swaymsg` や `hyprctl`）、それぞれが固有の依存を連れてきます。
存在するデスクトップの数だけ Recommends が増えていく単一パッケージ、というのが避けたい形です。

tar.gz は**意図的に分けていません**。「展開してすぐ動く」がその存在理由で、2つの書庫を正しい順序で
展開させるのはそれではありません。

## バージョンの並び方

nightly はビルド時刻とコミットをバージョンに持つので、`apt` は次の nightly へ**アップグレード**します。
古いファイルとして拒否しません。**それを成立させているのはチルダ**です。Debian は `~` を何よりも前に
並べます。何も無いことよりも前に:

```
0.1.0~20260828.1830.g462431a  <  0.1.0~20260829.0300.gdeadbee  <  0.1.0
```

nightly は昇順に並び、本物の `0.1.0` はすべての nightly を上書きします。`dragonperch --version` は
入っているものをそのまま表示します。

**ダウンロードしたファイル名では `~` が `.` になっています。** GitHub はリリース資産の名前から
`[A-Za-z0-9._-]` 以外を書き換えるためです。実害はありません。`dpkg` と `apt` がバージョンを読むのは
パッケージの control フィールドで、ファイル名は慣習であってデータではありません。確かめられます:

```bash
dpkg-deb -f dragonperch_*.deb Version
```

CI も毎回同じフィールドを表示し、リリース版より前に並ばなくなったらビルドを失敗させる
`dpkg --compare-versions` を併せて実行しています。

## Windows Defender がダウンロードを検知する

`Trojan:Win32/Wacatac.B!ml` — 手がかりは `!ml` で、これは署名一致ではなく機械学習による推測です。
誤検知であり、予想できる誤検知でもあります。バイナリは未署名で、作りたてで、まだ誰もダウンロードして
おらず、やっていることは他のアプリケーションのウィンドウの列挙、システム全体のイベントフックの設置、
画面全体を覆う透明な最前面ウィンドウの維持です。画面収集ツールとほぼ同じ振る舞いです。

正直な形でこれを消す小細工はありませんし、消せる小細工があるならそれ自体が疑わしいものです。本当の
答えは2つです。

- <https://www.microsoft.com/en-us/wdsi/filesubmission> に**誤検知として報告する**。これは効きますし、
  やる価値があります。自分だけでなく全員に対して検知されなくなる方法だからです。
- **署名する。** コード署名証明書はバイナリに身元を与え、評判を積ませます。それまでは新しいビルドは
  毎回ゼロからで、Defender が黙っていても SmartScreen が警告します。

自分でビルドすればこの問題は起きません。手元でコンパイルしたバイナリはダウンロードではないからです。
