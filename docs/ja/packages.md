# パッケージとダウンロード

英語版は [docs/packages.md](../packages.md) です。

`main` ブランチのビルドごとに、常に最新の **`nightly`** プレリリースが公開されます。また、CI が実行されるたびに同じファイルがアーティファクトとして14日間保存されます。どちらも同じ `install()` ルールから生成されるため、テストされたものと全く同じものが配布される仕組みです。

| ファイル | 使い方 |
|---|---|
| `dragonperch_0.1.0~…_amd64.deb` | `sudo apt install ./dragonperch_*.deb` |
| `dragonperch-kde_0.1.0~…_amd64.deb` | Plasma 専用: KWin スクリプトと KDE 設定モジュール |
| `dragonperch_0.1.0~…_x86_64.tar.gz` | 任意の場所に展開し、`usr/bin/dragonperch-wl` を実行 |
| `dragonperch_0.1.0~…_x64.zip` | 展開して `dragonperch.exe` を実行 |

## バージョンの規則

nightly ビルドは、バージョン番号にビルド日時とコミットハッシュを含みます。こうしておくと、`apt` は次の nightly をダウングレードとして拒むことなく、正しく**アップグレード**として扱ってくれます。

鍵になっているのが **チルダ（`~`）** です。Debian のバージョン比較では、`~` は何よりも前に来ます。文字が無いことよりもさらに前です。

```
0.1.0~20260828.1830.g462431a  <  0.1.0~20260829.0300.gdeadbee  <  0.1.0
```

おかげで nightly は古いものから順に並び、本物の `0.1.0` が出ればそのすべてを綺麗に追い越せます。`dragonperch --version` を実行すれば、インストールされているバージョンを正確に確認できます。

なお、**ダウンロードしたファイル名では `~` が `.` に変換されています。**
これは、GitHub がリリース資産（Release Asset）のファイル名から `[A-Za-z0-9._-]` 以外の文字を書き換えてしまうためです。とはいえ実害はありません。`dpkg` も `apt` もバージョンはパッケージ内部の `control` フィールドから読むので、ファイル名は慣習であってデータではないからです。ご自身でも確かめられます。

```bash
dpkg-deb -f dragonperch_*.deb Version
```

CI でも毎回この `control` フィールドを表示し、`dpkg --compare-versions` で「リリース版より前に並ぶこと」を確かめています。この規則が崩れればビルドが失敗します。

## Debian では2つ、それ以外は1つ

Debian 向けのパッケージは2つに分かれています。
`dragonperch` には、デーモン本体、アートワーク、翻訳、デスクトップエントリが含まれており、KWin についての知識は一切持っていません。
一方 `dragonperch-kde` は Plasma 専用のもので、KWin スクリプトと設定モジュールが含まれています。こちらは対応するバージョンの `dragonperch` にぴったり依存しており、逆にデーモン側もこれを `suggests` しています。Plasma のマシンに入れた人へ、もう半分の存在を知らせるためです。

分けたのは、今のためというより**この先のため**です。KWin 以外の環境でウィンドウの位置を知るには別の手段が要り（GNOME なら Shell 拡張、wlroots なら `swaymsg` や `hyprctl`）、そのどれもが固有の依存関係を連れてきます。世の中のデスクトップ環境の数だけ Recommends が膨らんでいく単一パッケージ、というのが避けたい形です。

一方 tar.gz は**意図的に分割していません**。「展開してすぐ動く」ことこそがその存在意義であり、2つのアーカイブを正しい順序で展開させるのは本末転倒だからです。そのため KWin スクリプトも `usr/share/kwin/scripts/` に同梱されています。

アートワークも、翻訳も、そのスクリプトも、実行ファイルからの相対パスで探されます。tar.gz は展開した場所でそのまま動き、インストールも環境変数も要りません。

パッケージをインストールしただけでは、KWin スクリプトが `kwinrc` で**有効になることはなく、ログイン時の自動起動も行われません**。その必要もありません。DragonPerch は起動のたびに自分でスクリプトを読み込みますし、何かの依存関係で勝手に入ってきたプログラムが、ユーザーの画面に突然マスコットを出現させるようでは、アンインストールされて当然だからです。詳しくは[動作条件](requirements.md)をご覧ください。

## Windows Defender がダウンロードを検知する

ダウンロード時に `Trojan:Win32/Wacatac.B!ml` といった警告が出ることがあります。手がかりは末尾の `!ml`（Machine Learning）です。これはシグネチャの一致ではなく、機械学習による推測であることを示しています。

これは誤検知ですが、予想はついていました。このバイナリは未署名で、ビルドされたばかりで、まだ誰にもダウンロードされておらず、その上「他のアプリケーションのウィンドウを列挙し、システム全体のイベントフックを仕掛け、画面全体を覆う透明な最前面ウィンドウを維持する」という、いわゆる画面収集ツール（スクリーン・スクレイパー）とほぼ同じ振る舞いをします。

この警告を消す魔法のような小細工はありませんし、あったとすればそれ自体が怪しいものです。実際の手立ては2つだけです。

- <https://www.microsoft.com/en-us/wdsi/filesubmission> から**誤検知として報告する**。これは非常に効果的であり、やる価値があります。あなただけでなく、全員に対して検知されなくなるからです。
- **コード署名を行う。** コード署名証明書はバイナリに身元を与え、評判を蓄積させるためのものです。署名がなければ、新しいビルドのたびに信頼度はゼロからやり直しで、Defender が黙っていても今度は SmartScreen が警告を出します。

ご自身でソースからビルドした場合は、インターネットからダウンロードしたファイルではないため、この問題は発生しません。

自分でビルドするには以下のようにします：
```bash
cmake --build --preset linux-x64-release && cd build/linux-x64 && cpack -C Release
```
