# DragonPerch を翻訳する

英語版は [docs/translating.md](../translating.md) です。

**文字列テーブルはプロジェクト全体で1つ**です。中にプログラムが3つあり（デーモン、Windows シェル、
KDE 設定モジュール）、仕組みが3つあれば同じ文が3回訳されて3通りにずれていくからです。

プログラムを動かすために何かをインストールする必要はありません。呼び出し側が英語を持っており、
その英語がフォールバックです。`lang` ディレクトリが無いビルドは、この仕組みが存在しなかった頃と
一字も変わらずに読めます。

## 言語を追加する

`lang/ja.ini` をコピーし、言語タグの名前に変えて、右辺を訳します。

```ini
[Strings]
menu.pause = Pausa
menu.quit = Chiudi DragonPerch
```

置き場所は実行ファイルの隣の `lang/`、インストール済みなら `share/dragonperch/lang` です。
アートワークと同じ規則なので、展開しただけの書庫でもインストールせずに動きます。

`ja.ini` は `ja`・`ja-JP`・その他 `ja-` で始まるものすべてに使われます。地域ごとに語を変える必要が
あれば `pt-br.ini`、無ければ `pt.ini`。より具体的なほうが勝ちます。

**小文字で、ハイフンです。** システムが報告する値は探す前に正規化され、`ja_JP.UTF-8` も `ja-JP` も
`ja-jp` になります。`pt-BR.ini` という名前は Windows では見つかり Linux では見つからないという、
2つのうち悪いほうの間違い方をします。

訳されていないキーはひとりでに英語へ落ちます。**部分訳も有用な訳です** — 全部埋めてから出す必要は
ありません。

ひとつ制約があります。訳文に `;` と `#` は使えません。両方のパーサがコメントの開始として行を切ります。
必要な言語には全角の `；` `＃` があり、日本語の文ならそもそもそちらを使います。

## なぜキーが英語ではなく id なのか

`menu.pause = 一時停止` であって、`Pause = 一時停止` ではありません。

理由は2つ、どちらも実務的です。このファイルは INI で、英文には `=` や `;` や `#` が入り得ます。
そのどれもがこの形式では区切りかコメントです。そして英語の書き直しは起こります。英語をキーにすると、
その文字列の訳は**すべて黙って外れ**、症状はページの半分が別の言語になることだけです。

代わりに、呼び出し側が文字列を2回名指しすることになります:

```cpp
tr("menu.pause", "Pause")
```

これが同時に、英語のカタログを配らなくてもフォールバックが働く理由でもあります。

## どこに何があるか

| | |
|---|---|
| `src/core/dragonperch/language.hpp` | テーブル本体と `tr` |
| `lang/*.ini` | カタログ |
| `src/win/tray.cpp`, `src/linux/tray.cpp` | トレイメニュー |
| `shell/windows/Strings.cs` | 同じカタログを読む Windows シェル側 |
| `kcm/` | KDE 設定モジュール（QML から `kcm.text(id, english)`） |

Windows の設定ウィンドウは、コードに英語をもう1つ持つのではなく**マークアップにある文をそのまま
フォールバックに使います**: `Strings.Get("settings.pets", PetsTitle.Text)`。英語の在処は1箇所だけで、
訳されていない id は要素をそのまま残します。

どの言語かは各プログラムが OS に尋ねます。コアは尋ねることを許されていないからです。Windows は
`GetUserPreferredUILanguages`、Linux は `LC_ALL` / `LC_MESSAGES` / `LANG` の順、Windows シェルは
`CultureInfo.CurrentUICulture`、設定モジュールは `QLocale::system().uiLanguages()`。

どちらもロケールではありません。ロケールは数値の見た目、UI 言語は語であり、両方のシステムが両者を
別々に設定できます。`LC_ALL=C` と `LANG=ja_JP.UTF-8` が同時にあれば正しく英語になります。確認済みです。

`dragonperch.log` に、どのカタログが読まれ何語入っていたかが出ます。
